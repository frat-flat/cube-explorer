## D-001 Card は Box の属性にする(2026-10-08 ユーザー決定)

- ② 5章のとおり。Card は必ずどれか1つの Box に付き、その Box が何者かを表す属性の集まりにする。
- 属性1つごとに、項目(Column Registry のカラム)・値・期間(`valid_from`・`valid_to`)・元(`source_reference`)を持つ。
  - 期間: 例「課税区分 = 免税事業者(2023-04-01〜2025-03-31)、課税事業者(2025-04-01〜)」。その時点の正しい値で表示・絞り込みできる。スプシに期間がない項目は「期間なし」で入れ、変わったときに区切る。
  - 元: スプシから移した値はそのセル(例「法人台帳 › 2025 › D12」)、4D Base で入力・修正した値はその記録。
- Card を一覧表の代わりにしない。Import の「1行ずつ Card にする」は「1行ずつ Box にして、その行の列を Box の Card にする」に変える。
- ① 付録の未決「Card の扱い」はこれで決定。

## D-002 スプシは移行元。スプシごとに「移行完了」で 4D Base を正本にする(2026-10-08 ユーザー決定)

ユーザーの言葉:「スプシは移行前のデータとして取り扱うため、完全に4DBに移行したらアプリ内で修正できるようにする必要がある」。

| 状態 | 正本 | 値を直す場所 | スプシの読み直し |
|---|---|---|---|
| 移行中 | スプシ | スプシで直して読み直す(4D Base では直さない) | できる |
| 移行完了 | 4D Base | 4D Base で直す。元の値・直した値・日時を履歴に残す | しない(スプシは移行元の記録として残す) |

- 「移行完了」はスプシ(またはタブ)ごとに切り替える。少しずつ移せる。
- どの状態でも、合計・計算の値は直せない(元の値を直すと計算し直される)。② 30章の「Derived Value を Raw Value として保存しない」を守る。
- 元のスプシを 4D Base から書き換えない(① 30章)。
- ① は「スプシを Source として読み続ける」書き方になっている。この移行の流れは ① にまだない(① を直すときに 29章 Import へ反映する)。

## D-004 芯・つなぎ・入れ物に分ける(フランチャイズ化に備える)(2026-10-08 ユーザー決定)

ユーザーの言葉:「ある程度固まったら4DBをフランチャイズ化したい。つまり4DBは4DBとしての設計を保ったままSynapseのプロジェクトに組み込んでカスタマイズしていきたいからそれに沿ったつくりにして」。

| 部分 | 中身 | 組み込み先ごとに |
|---|---|---|
| 芯 | データモデル、集計・投影、取り込みの決まり、D-001・D-002 などの決まり | 変えない(4DB の設計そのもの) |
| つなぎ | 保存先(素の Postgres)、ログイン(誰のデータか)、取り込み元(Google スプシなど) | 差し替える |
| 入れ物 | この Next.js アプリ、将来の Synapse | 画面・ブランド・追加機能 |

- 芯は同じリポジトリの中で別の場所に置き、Next.js・React・ログインの仕組み・Neon や Supabase に固有の機能に依存しないことを自動チェックで守る。Synapse への組み込みを始めるときに部品として切り出す。
- 芯の表は専用の名前空間に置き、組み込み先のデータベース(Synapse なら Supabase)に同居してもぶつからないようにする。
- 「誰のデータか」は入れ物から芯へ渡す。芯はログインの仕組みを直接呼ばない。

## D-017 ホームは World の舞台に、立体の Box を並べる(2026-10-10 ユーザー決定。D-016 の P2 の中身)

- 中の部品の数(ファイル・Box・カラムなど)を並べるホームはやめる。4DB をサービスにしたとき、入れるデータが違っても同じ形になるホームにする。
- ホームには Box だけを置く。いちばん上の Box(親のない Box)を単位ごとにまとめ、1 単位を 1 つの立体にする。立体は台座の上に浮かび、ゆっくり回る。
  - 押すと、その単位の中身(名前・中・Card の項目・数値・期間・元のシート・Table、のちに Cube と数字の帯)を横に出す。欄の並びはどの利用者でも同じにし、値がない欄は「—」と出す。
  - 親子(P3・P4)ができると、同じ決まりのまま「法人(中に店舗)」のような大枠になる。
  - 全期間を足した数値の合計は出さない(残高や率では意味が崩れるため)。最新の期間の数字は T(P11)のあとで足す。
